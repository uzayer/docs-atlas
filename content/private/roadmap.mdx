**Everything on this page describes work that has not shipped.** None of it is available in Atlas today, and nothing here should be read as a description of how the app currently behaves. Every other page in these docs describes what exists now; this one is the single place where unbuilt work is written down.

There are no dates on this page, because nobody has committed to any.

<Callout type="warn">
  If you arrived here from a search result, note the page you're on. The features below are **not** in Atlas. For what Atlas actually does today, start with [Getting Started](/docs).
</Callout>

## Multiplayer AI

**Not shipped. The capture half is built; the reading half is not.** This is the direction the rest of this page points at.

Atlas today is single-player. You run agents against your own checkout, your [memory](/docs/context/memory) is on your device, and your [timeline](/docs/source-control/timeline) is your own record. Your team already shares the repository, and git handles that well. What it doesn't share is everything around the code: what an agent was asked, what it tried, why a change is shaped the way it is.

The ambition is teammates and agents working from the same live context, not merely the same repo. The reasoning behind a change is available to the next person who touches it, whoever they are, and an agent picking up work inherits what the last agent and the last human both knew.

It splits into two halves. Getting each developer's sessions into the organization is team capture, below, and it is nearly done. Reading them back as a shared record is the team timeline, further down, and it has not started in the client.

## Team capture

**Not shipped: built in the client, switched off by one flag.**

Session capture ships today in Local mode (see [Session capture](/docs/source-control/capture)). Everything needed to send a project's sessions to its organization is also in the app:

- **Create as Cloud.** Register the project with the active organization under a slug. Slug availability is checked as you type.
- **Connect.** Join a project a teammate already registered. Atlas pre-selects the match by root commit and origin URL, and refuses to guess when several projects share a root commit (repositories made from one template do).
- **Promote.** Move a Local project to Cloud and bring its history. There is no separate backfill path: local rows join the same queue as new ones.
- **Disclosure with real numbers.** Importing history and promoting both stop on a confirmation showing session count, date range, and secrets redacted. Nothing is sent until you confirm, and canceling leaves the project exactly as it was.
- **An offline-first queue.** Capture never waits for the network. Rows queue as pending and drain when they can. A blob uploads before the row that references it, so a teammate never opens a message whose body is missing. A `403` stops the drain as "no longer authorized" and local capture carries on.
- **No local paths on the wire.** Records carry the server-assigned project id, never the folder path.

Cloud follows the active organization only, and it needs you signed in to a cloud (or synced) organization.

What remains is `CLOUD_CAPTURE_ENABLED` in the capture popover, which is still `false`. Until it flips, Cloud and Connect render disabled with "Cloud capture isn't available yet", no project can enter Cloud mode, and **zero bytes leave your machine**. The ingest service now answers its read routes (they return `401` unauthenticated, not the `405` the flag's comment describes), so the flag is the last client step.

## A team timeline

**Not built.** The [timeline](/docs/source-control/timeline) is organization-scoped (it spans every project in the active organization) but single-user: it reads only this machine's local stores.

Three things make that concrete:

- **There is no inbound path.** Team capture sends sessions to the organization. Nothing in the app reads a teammate's sessions back.
- **Authorship is the server's job.** A record carries no author field, because a client can claim anything. The ingest service stamps who sent it. Nothing in the app displays that yet.
- **Git identity is not account identity.** Commits carry an author name and email, and Atlas records them for display only. They're self-asserted, so they are never mapped to an organization member.

A shared timeline would mean seeing which sessions produced which commits across everyone working in a repository, not just your own.

## Spaces

**Built, but not a priority, and possibly moving.**

Spaces is the canvas: a per-project board for laying work out visually. It exists in the app and works. It is not where most of the effort is going, and it may move from project scope to organization scope, which would change where a board lives and who can reach it.

Because that scope question is open, it isn't documented in Product. Treat it as present but unsettled rather than planned.

## The browser

**Partly built.** What exists is a browser panel: an embedded webview you can open beside your work, read pages in, and save from, plus the plumbing that keeps it from painting over dialogs.

What isn't built is the reason it's on this page. The intent is for the browser to be somewhere an agent can drive a real page and author tests against what it sees, rather than a viewer that happens to live in the window. None of that exists today.

## Atlas's own agent

Atlas's [native agent](/docs/agents) ships today, so this section is only about what it can't do yet.

**Image input is not supported.** Paste a screenshot into a turn and it reaches the native agent as a file path rather than as an image. The third-party agents that support vision handle it properly, so this is a gap specific to Atlas's own agent.

Beyond that, the native agent is where capabilities that depend on running in-process (rather than over a protocol) get built first. It already has direct memory retrieval and subagent delegation for that reason.

## Smaller things not built yet

Each of these is a control or behavior you may actually encounter, so they're written down rather than left to be discovered.

- **European hosting for organizations.** The region selector in the create-organization form shows European Union, grayed out. Only United States is hosted. It's shown rather than hidden so the choice is visibly coming rather than absent.
- **Invitation emails.** Inviting someone to an organization does not send them an email. The accept link is copied to your clipboard and you pass it on yourself. See [members and invitations](/docs/organization/members).
- **Usage reporting for every agent.** [Usage](/docs/context/usage) reads Atlas's captured session record for every agent. Token detail appears when the agent reports it, and an unknown or unpriced model contributes no estimated cost.
- **The block terminal on shells other than zsh.** Command blocks depend on shell integration Atlas installs for zsh. Other shells run fine but present as a single plain stream. See [Terminal](/docs/product/terminal).
