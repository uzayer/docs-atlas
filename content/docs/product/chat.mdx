Open a session to work with one [agent](/docs/getting-started/concepts#agent). Atlas records the conversation as a [session](/docs/getting-started/concepts#session), including its file reads, commands and edits.

This page is about working with an agent. To message your teammates, see [Team chat](/docs/team/chat).

<Screenshot src="/screenshots/product/agent-chat.png" alt="A session: the transcript with a finished turn and its summary of changed files, and the composer below showing the agent, mode and model controls." caption="A session." />

## Start or resume a session

Choose **New session** at the top of the sidebar, or in the session's header, to start a session. It opens in the main column. To run a second session beside it, press <Kbd>⌘T</Kbd> then <Kbd>A</Kbd>, which opens one in the [surfaces pane](/docs/product/power-user#surfaces).

When you reopen a session, Atlas paints the transcript from disk while the agent reconnects.

Atlas Agent needs an organization that is synced to your account and has AI access. If the composer says so instead of letting you type, see [AI access & spend](/docs/team/ai-access).

## Find your sessions in the sidebar

The sidebar lists your sessions across every project in the organization, newest activity first, with each row's project, branch and status. <Kbd>⌘⇧.</Kbd> or <Kbd>⌘⌥J</Kbd> shows or hides it. Click the session title in the header to search for a session.

- **The project picker** at the very top narrows the list to one project. It shows **All projects** or the chosen project's name, and stays set until you change it. Its menu lists the organization's projects, with a search field once there are more than six; right-click a project, or click its gear, to open its settings. It also holds **Add project**, **Import sessions from agents…** and, at the bottom, the organization (see [Organizations](/docs/team/organizations#find-your-way-around-the-sidebar)). The magnifier beside it opens the command palette.
- **Search** below it finds a session by title, project or branch. Use the arrow keys to move through the results and <Kbd>Enter</Kbd> to open one.
- **Pinned** sessions stay at the top. Drag a pinned session to reorder it, drag it down into the list to unpin it, or drag a session up onto the pinned ones to pin it.
- **Unread** sessions are marked when an agent finishes a turn you haven't seen.
- **Snoozed** sessions move to the **Snoozed** shelf, above Settled, until the time you picked, then come back to the list marked **Woke**. The shelf is collapsed until you open it and shows its count; each row there shows how long until it wakes, and **Wake** brings it back now.

Rest the pointer on a session for a moment to see its project, agent and model, branch and pull request, whether it is shared with the team, and how many comments it has. Use <Kbd>↑</Kbd> and <Kbd>↓</Kbd> to move between sessions and <Kbd>Enter</Kbd> to open one.

Right-click a session, or choose **⋯** on it, for everything else:

- **Pin** or **Unpin**
- **New session on** its branch. For a session in a worktree, the new session starts in that worktree. Otherwise Atlas checks the branch out in the project first, and refuses if the project has uncommitted changes or an agent is working there, offering to start on the current branch instead.
- **Settle** or **Unsettle**
- **Snooze**, for a preset time or a custom one, or **Wake session** on a snoozed one
- **Rename**
- **Mark unread** or **Mark read**
- **Filter by** its project
- **Copy** its title, path, branch or session ID
- **Open in** your editor
- **Project settings**
- **Delete**

## Settle a session

Settle a session when you are done with it for now. Hover it and choose **Settle**, or press <Kbd>⌘⌥S</Kbd> on the open one. It moves to the **Settled** shelf at the bottom of the sidebar and the next session opens; **Undo** in the notice brings it back. Sending a message to a settled session moves it back to the list. Atlas also settles sessions that have been idle for 3 days, but never one that is running or waiting for you. Change the number of days, or turn it off, with **Settle idle sessions after** in Settings → Sessions.

The Settled shelf is collapsed until you open it. It has its own search, and **Show more** pages through older sessions. A settled session that is open or running stays visible even while the shelf is collapsed.

## Bring in sessions from your agents

Open the project picker at the top of the sidebar and choose **Import sessions from agents…** to pull in sessions an agent kept on its own, such as ones you ran in a terminal. Imported sessions land on the Settled shelf.

Atlas asks each installed agent for its session list. An agent that cannot list its sessions still appears, grayed out, with the reason.

## Choose and switch agents

<Video youtube="BNfkFyrH86I" title="Bringing your coding agents to Atlas" />

Choose the agent from the composer, or press <Kbd>⌥/</Kbd> to cycle through them. A session belongs to one agent, so what happens when you switch in a session that already has a conversation depends on **Switching agents in a session** in [Settings → Sessions](/docs/product/settings#sessions):

- **Start over** switches in place with a clean session. This is the default.
- **New tab** keeps the conversation on screen and opens the new agent beside it.
- **Hand off** switches in place and attaches the conversation to your next message, so the new agent picks up where the last one stopped.

Every conversation stays in your history either way. Turn on **Save to memory before switching agents** to have the agent you are leaving save what it learned to [shared memory](/docs/context/memory) first.

## Give the agent direction

The composer shows the controls the connected agent advertises, such as the permission mode, model and reasoning effort. Press <Kbd>⇧Tab</Kbd> to cycle the permission mode.

<Kbd>Enter</Kbd> sends and <Kbd>⇧Enter</Kbd> adds a line. <Kbd>⌘Enter</Kbd> always sends. To make <Kbd>Enter</Kbd> add a line instead, turn off **Enter to send** in Settings → Sessions.

### Add context

Type `@` to mention context: files, folders, symbols, knowledge notes, pack components, repositories, other projects, branches, and earlier messages or sessions. In a project shared with your organization through cloud capture, you can also mention teammates, team conversations, recorded sessions and comments. Atlas shows larger references below your message so you can see what the agent receives.

Paste more than 4,000 characters or 80 lines and the text becomes a chip in the composer, so your message stays readable. The agent still receives all of it, and editing a queued message keeps the chip.

The **+** button in the composer adds context too:

- **Add files**, or **Add files or photos** when the agent accepts images
- **Attach media**, including **Take a screenshot** of a region or the whole desktop
- **Add from GitHub** to clone a repository for reference
- **Attach a session** to bring in an earlier session
- **Reference project** to point at another project

### Attach other projects

A session can work in folders besides its own. When you mention another project or a repository, or clone one with **Add from GitHub**, Atlas attaches it to the session. An attached project stays with the session: it is still there on later messages and when you resume the session.

A project is attached **read-only** at first: the agent can read it but not change it. The chip in the composer shows the access. Click its eye icon to let the agent edit files there, and click the pencil to make it read-only again. Atlas tells the agent what it may do in each attached project.

Atlas Agent can write to a project from its next turn. Other agents get write access the next time the session is resumed, and Atlas says so when you grant it.

Atlas never attaches the root of your disk, your home folder, a system folder, or a settings folder such as `~/Library` or `~/.ssh`.

#### When the agent asks for access

When code tools are on, an agent can ask to use a folder outside the session. Atlas shows the request in the session with the folder and the agent's reason. Choose **Allow read and write**, **Allow read-only**, or **Deny**. The agent is told your answer. If you approve after the agent has stopped waiting, the folder is still attached and the agent can use it once it asks again.

### Run a command

Type `/` to run one of the agent's own commands or [skills](/docs/context/skills). The list is what the agent advertises, and Atlas sends the command through unchanged. The one command Atlas adds is `/login`, which opens the agent's sign-in.

## Steer a running turn

Messages you write while an agent works join a queue. Edit or remove them before they run. Plans appear above the composer, and permission requests show the agent's own choices.

When Atlas Agent needs an answer to continue, it asks you in the session and waits.

Stop is always available. For a transient provider failure, Atlas shows the retry countdown and the reason.

## Review the result

While the agent works, the turn shows how long it has been working and what it is doing right now. When it finishes, its work folds behind **Worked for** and the time, leaving the answer in view. Each block of tool calls is summarised by what it did, such as "Ran 3 commands and read 2 files", and a call that failed stays in view after the fold. Select **Worked for** to see every step, with how long each one took. A turn you stop reads **Stopped after** instead, with the time it ran.

Every turn ends with a summary of how long it worked and the files it read or changed, with lines added and removed. Choose **Show changes** to open the turn's diff, or **Save** to keep the conversation as a [knowledge base](/docs/context/knowledge-base) note.

The usage pill in the composer shows how full the agent's context window is, along with tokens and cost when the agent reports them.

With **Next-step suggestions** on in Settings → Sessions, the agent offers two or three follow-ups as chips after each turn. Click one to send it.

## Work with messages

Hover a message, or Tab to it, to show the row of actions under it along with the time it was sent. Hover the time for the full date. On a response that changed files, the row sits under the changed-files summary, at the end of the response. Messages from a session the agent reloaded from its own history show no time, because the agent doesn't record one.

- **Copy** the prompt or response as markdown
- **Retry** your latest prompt to replace its response
- **Pin** a prompt or response, then find it again from the pinned messages menu in the session header. Pins are kept on your machine.
- **Branch from here**, on the latest response, copies the session into a new one when the agent supports it
- **More** (…) on a prompt holds **Edit and send as new message**, to rework it

File paths in messages appear as chips with your [icon theme's](/docs/themes/icon-themes) file icons. That covers paths the agent writes, such as `src/lib/api.ts:42`, and the files and folders you mention with `@`. Select a chip, or press <Kbd>Enter</Kbd> on it, to open the file in a tab at the line it names. A path written without its folder opens the one project file it matches. A file outside the project opens in your [preferred editor](/docs/product/editor#open-in-your-editor), or the app your system uses for it. A folder or an app is shown in Finder, never run. In the agent's replies, only paths inside the project are clickable.

Web links are shown in a link colour, and are underlined when you hover or Tab to them. They show the service's icon before the link text: GitHub, GitLab, Bitbucket, Codeberg, Linear, Slack, Notion, Figma, Vercel and npm have their own, and other sites show a globe. A bare link to a pull request, issue, commit or repository, or to a Linear issue, is shortened to `PR #42`, `#17`, the short commit hash, `owner/repo` or `ATL-978`. Hover the link to see the full address. Copied text includes the full address.

Select text in a response and choose **Cite** to point the agent at that passage. Add a note if you like, then **Cite** again to drop a chip into the composer. When you send, the agent gets the quoted passage (up to 2,000 characters) and your note. A cite is private to your agent. On a session shared with your organization, turn on **Share with team** to also post the passage and your note as a comment; a shared cite needs a note.

Search long sessions with <Kbd>⌘F</Kbd>. The header's **More** menu filters the transcript to your messages or the agent's, and opens the **Bash calls** and **Plans** panels, which collect commands and plans without expanding the transcript. When the agent supports it, **Branch from here** in the same menu copies the session into a new one so you can try another direction.

### Jump between turns

A column of short ticks down the left edge of a session marks its turns, one tick per prompt and the agent's reply. The ticks for the prompts on screen are brighter. Hover a tick to see its prompt and the start of the reply, and click it to jump there; the arrows above and below the column step to the previous or next turn. Tab to the column and use <Kbd>↑</Kbd>, <Kbd>↓</Kbd>, <Kbd>Home</Kbd> and <Kbd>End</Kbd> to move through turns, then <Kbd>Enter</Kbd> to jump.

The column shows once a session has two turns. In a long session the ticks move closer together rather than running off the screen. When the window is too narrow to leave room beside the conversation, the column appears only while you hover the left edge. Turn it off with **Turn rail** in Settings → Appearance.

## Session context

Click the session context button (≡) in the main header for everything around the session, in one card.

When the window is wide enough, the card docks at the top-right of the session, beside the conversation, and the button shows or hides it. The conversation already leaves room for the card, so showing or hiding it never moves what you are reading. In a narrower window, or while the overview panel is open, the card opens as a popover instead.

The card holds:

- **The machine** the session runs on, with the project folder's path in the folder icon's tooltip.
- **Open in your editor**: the editor chosen under **Preferred editor**, or the first one Atlas finds. Its menu lists your other editors, then **Reveal in Finder**, **Open in Terminal** and **Copy path**.
- **Project scripts**: named commands for the project, such as a dev server or the tests. Click one to run it in a terminal at the project root; the menu lists them all, with a pencil to edit each. Choose **Add project script** to create one. Scripts are saved in the project's `.atlas/config.toml`, so they travel with the repository.
- **The branch**, with a picker. Type to filter your local branches, or enter a new name and choose **Create branch** to create it and switch to it.
- **Pull requests** opened from the branch: the open one first, with a check mark or cross for its checks, and earlier ones behind **Show more**. Click one to open it on GitHub.
- **The next git action**, such as **Create PR**, **Push & create PR**, **Commit & push…**, **Pull** or **Push**. **Create PR** pushes the branch if it needs it, then shows the title and description the pull request would open with, for you to edit before it is created. The menu holds **Create draft PR**, **Pull**, **Push** (or **Publish branch**), **Fetch** and **Open Source Control**. The default branch is never offered a pull request.
- **Changes**: the lines the session added and removed. Click it to open the session's diff. With no session changes, it counts the project's uncommitted files and opens [source control](/docs/source-control/git).
- **The agent and model** the session runs on.
- **Usage**: the context window, tokens and cost.
- **Capture**: whether [session capture](/docs/source-control/capture) is recording this project. Click it to set capture up without leaving the card.
- **Lineage**: the session this one was branched from with **Branch from here**, the sessions branched from it, and the agents it delegated work to. Click a session to open it.

A dot on the button shows capture's state while it records: green when it is on, amber when it is degraded, red when it has stopped. Press <Kbd>⌘⌥C</Kbd>, or run **Open Session Capture** from the command palette, to open the card straight on Capture.

## See your team's comments

<Video youtube="bDvUsOU3dyA" title="Reviewing agent work together" />

When a session is shared with your organization through [cloud capture](/docs/source-control/capture), teammates can comment on it from the [timeline](/docs/team/timeline). Their comments appear on the matching messages in your session as they arrive.

Click the comments button (speech bubble) in the session header to see every thread on the session, reply, or add a comment of your own. Each message and tool call has its own comment button too, which shows when you hover it.
