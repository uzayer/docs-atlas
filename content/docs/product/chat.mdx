Open a session to work with one [agent](/docs/getting-started/concepts#agent). Atlas records the conversation as a [session](/docs/getting-started/concepts#session), including its file reads, commands and edits.

This page is about working with an agent. To message your teammates, see [Team chat](/docs/team/chat).

<Screenshot src="/screenshots/product/agent-chat.png" alt="A session: the transcript with a finished turn and its summary of changed files, and the composer below showing the agent, mode and model controls." caption="A session." />

## Start or resume a session

Choose **Agents** in the sidebar, or **New session** in the session's header, to start a session. It opens in the main column. To run a second session beside it, press <Kbd>⌘T</Kbd> then <Kbd>A</Kbd>, which opens one in the [surfaces pane](/docs/product/power-user#surfaces).

Your recent sessions are listed in the sidebar. Open the agent sidebar with <Kbd>⌘⌥J</Kbd> to search and reopen the sessions of the projects you are working in, or to archive or delete one.

Settle a session when you are done with it for now. Hover it and choose **Settle**, or press <Kbd>⌘⌥S</Kbd> on the open one. It moves to the **Settled** shelf at the bottom of the list and the next session opens; **Undo** in the notice brings it back. Sending a message to a settled session moves it back to the list. Atlas also settles sessions that have been idle for 3 days, but never one that is running or waiting for you. Change the number of days, or turn it off, with **Settle idle sessions after** in Settings → Sessions.

When you reopen a session, Atlas paints the transcript from disk while the agent reconnects.

Atlas Agent needs an organization that is synced to your account and has AI access. If the composer says so instead of letting you type, see [AI access & spend](/docs/team/ai-access).

## Bring in sessions from your agents

The **All history** button at the top of the agent sidebar lists every session you have run in Atlas, archived ones included. Choose **Import** there to pull in sessions an agent kept on its own, such as ones you ran in a terminal.

Atlas asks each installed agent for its session list. An agent that cannot list its sessions still appears, grayed out, with the reason.

## Choose and switch agents

<Video youtube="BNfkFyrH86I" title="Bringing your coding agents to Atlas" />

Choose the agent from the composer, or press <Kbd>⌥/</Kbd> to cycle through them. A session belongs to one agent, so what happens when you switch in a session that already has a conversation depends on **Switching agents in a session** in [Settings → Sessions](/docs/product/settings#sessions):

- **Start over** switches in place with a clean session. This is the default.
- **New tab** keeps the conversation on screen and opens the new agent beside it.
- **Hand off** switches in place and attaches the conversation to your next message, so the new agent picks up where the last one stopped.

Every conversation stays in your history either way. Turn on **Save to memory before switching agents** to have the agent you are leaving save what it learned to [shared memory](/docs/context/memory) first.

## Give the agent direction

The composer shows the controls the connected agent advertises, such as the permission mode, model and reasoning effort. Press <Kbd>⇧Tab</Kbd> to cycle the permission mode.

<Kbd>Enter</Kbd> sends and <Kbd>⇧Enter</Kbd> adds a line. <Kbd>⌘Enter</Kbd> always sends. To make <Kbd>Enter</Kbd> add a line instead, turn off **Enter to send** in Settings → Sessions.

### Add context

Type `@` to mention context: files, folders, symbols, knowledge notes, pack components, repositories, other projects, branches, and earlier messages or sessions. In a project shared with your organization through cloud capture, you can also mention teammates, team conversations, recorded sessions and comments. Atlas shows larger references below your message so you can see what the agent receives.

Paste more than 4,000 characters or 80 lines and the text becomes a chip in the composer, so your message stays readable. The agent still receives all of it, and editing a queued message keeps the chip.

The **+** button in the composer adds context too:

- **Add files**, or **Add files or photos** when the agent accepts images
- **Attach media**, including **Take a screenshot** of a region or the whole desktop
- **Add from GitHub** to clone a repository for reference
- **Attach a session** to bring in an earlier session
- **Reference project** to point at another project

### Run a command

Type `/` to run one of the agent's own commands or [skills](/docs/context/skills). The list is what the agent advertises, and Atlas sends the command through unchanged. The one command Atlas adds is `/login`, which opens the agent's sign-in.

## Steer a running turn

Messages you write while an agent works join a queue. Edit or remove them before they run. Plans appear above the composer, and permission requests show the agent's own choices.

When Atlas Agent needs an answer to continue, it asks you in the session and waits.

Stop is always available. For a transient provider failure, Atlas shows the retry countdown and the reason.

## Review the result

While the agent works, the turn shows how long it has been working and what it is doing right now. When it finishes, its work folds behind **Worked for** and the time, leaving the answer in view. Each block of tool calls is summarised by what it did, such as "Ran 3 commands and read 2 files", and a call that failed stays in view after the fold. Select **Worked for** to see every step, with how long each one took. A turn you stop reads **Stopped after** instead, with the time it ran.

Every turn ends with a summary of how long it worked and the files it read or changed, with lines added and removed. Choose **Show changes** to open the turn's diff, or **Save** to keep the conversation as a [knowledge base](/docs/context/knowledge-base) note.

The usage pill in the composer shows how full the agent's context window is, along with tokens and cost when the agent reports them.

With **Next-step suggestions** on in Settings → Sessions, the agent offers two or three follow-ups as chips after each turn. Click one to send it.

## Work with messages

Hover a message, or Tab to it, to show the row of actions under it along with the time it was sent. Hover the time for the full date.

- **Copy** the prompt or response as markdown
- **Retry** your latest prompt to replace its response
- **Pin** a prompt or response, then find it again from the pinned messages menu in the session header. Pins are kept on your machine.
- **Branch from here**, on the latest response, copies the session into a new one when the agent supports it
- **More** (…) on a prompt holds **Edit and send as new message**, to rework it

Select text in a response and choose **Cite** to point the agent at that passage. Add a note if you like, then **Cite** again to drop a chip into the composer. When you send, the agent gets the quoted passage (up to 2,000 characters) and your note. A cite is private to your agent. On a session shared with your organization, turn on **Share with team** to also post the passage and your note as a comment; a shared cite needs a note.

Search long sessions with <Kbd>⌘F</Kbd>. The header's **More** menu filters the transcript to your messages or the agent's, and opens the **Bash calls** and **Plans** panels, which collect commands and plans without expanding the transcript. When the agent supports it, **Branch from here** in the same menu copies the session into a new one so you can try another direction.

## Session context

Click the session context button (≡) in the main header for everything around the session, in one overlay:

- **The project folder**, with **Open in Finder**. Its menu also has **Open in Terminal** and **Copy path**.
- **The branch**, with a picker to switch to another one.
- **The next git action**, such as **Commit & push…**, **Pull**, **Push** or **Publish branch**. Its menu holds the others: **Pull**, **Push** (or **Publish branch**), **Fetch** and **Open Source Control**.
- **The pull request** for the branch, when it has one.
- **Changes**: the lines the session added and removed. Click it to open the session's diff. With no session changes, it counts the project's uncommitted files and opens [source control](/docs/source-control/git).
- **The agent and model** the session runs on.
- **Usage**: the context window, tokens and cost.
- **Capture**: whether [session capture](/docs/source-control/capture) is recording this project. Click it to set capture up without leaving the overlay.

A dot on the button shows capture's state while it records: green when it is on, amber when it is degraded, red when it has stopped. Press <Kbd>⌘⌥C</Kbd>, or run **Open Session Capture** from the command palette, to open the overlay straight on Capture.

## See your team's comments

<Video youtube="bDvUsOU3dyA" title="Reviewing agent work together" />

When a session is shared with your organization through [cloud capture](/docs/source-control/capture), teammates can comment on it from the [timeline](/docs/team/timeline). Their comments appear on the matching messages in your session as they arrive.

Click the comments button (speech bubble) in the session header to see every thread on the session, reply, or add a comment of your own. Each message and tool call has its own comment button too, which shows when you hover it.
