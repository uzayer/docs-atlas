Use a [skill](/docs/getting-started/concepts#skill) to give an agent a named instruction it can invoke. Use a [pack](/docs/getting-started/concepts#pack) to install several skills, commands, agents, rules, hooks, or scripts together.

Manage both in **Settings → Skills**.

<Video title="Giving agents memory and context" />

## Choose the scope

Make a skill **global** to use it in every project, or **project** to keep it in one. Enable each skill only for the supported targets that should receive it.

Atlas keeps one canonical copy of each skill in the same place the skills.sh tooling uses: `~/.agents/skills` for global skills and `<project>/.agents/skills` for project skills. There is no separate Atlas store.

From there, Atlas links each skill into the skill directories of the agents you enable it for. The targets are **Atlas** (that's Atlas Agent), **Claude Code** and **Codex**. A registry agent is not automatically a skill target merely because it speaks ACP.

A skill that already lives in one agent's own directory shows up too, marked **external**. Atlas lists it but leaves it where it is; there's no button to move it into the canonical store. Skills that come from Claude Code plugins are listed read-only, since their plugin manages them.

Atlas installs two skills of its own into `~/.agents/skills`: `remember`, which saves a conversation to [shared memory](/docs/context/memory#save-a-conversation-with-remember), and `atlas-self-configure`, which lets an agent read and safely change your Atlas settings when you ask it to.

## Install a pack

Search the skills.sh registry, preview a pack, then install it. Atlas fetches the source repository, tracks the installed version in a lockfile, and can check for updates.

Skills become invokable instructions. Commands, agents, and rules from the pack become items you can [mention](/docs/getting-started/concepts#mention) in the composer.

## Invoke a skill

Type `/` in the [composer](/docs/product/chat) and choose a skill. The list is exactly what the current agent advertises, so a skill appears once the agent has found it in its directory. The list can be empty for the first few seconds of a session.

If an agent does not expose skills or commands through ACP, Atlas does not invent a way to invoke them.

<Callout type="info">
  A passthrough command runs only when it starts the message. Atlas sends it as ordinary text when it appears mid-sentence.
</Callout>
