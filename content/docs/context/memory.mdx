Start a new agent without starting from zero. Atlas indexes the context agents leave behind and brings back the useful parts when you send your next message.

## Let Atlas handle the handoff

Agents write instruction files, notes, and other persistent context as they work. Atlas indexes those files continuously, matches them to your prompt, and gives the strongest results to the agent.

Embedding runs on your machine, so Atlas does not send this text elsewhere. It also uses a low-weight graph of structured facts, but a graph match never outranks a stronger direct match.

Most agents receive relevant context in the turn. [Atlas Agent](/docs/agents/atlas) can search memory itself while it works.

## Carry durable preferences further

Atlas promotes only high-confidence preferences and constraints that appear in more than one project to cross-project memory. It uses that memory only when the current project has little relevant context.

## Inspect or correct memory

Open the Memory panel when you want to see what Atlas knows:

- **Graph** shows structured facts and their connections.
- **[Agent preferences](/docs/context/agent-preferences)** shows editable rules Atlas found in your files.
- **Timeline** puts memory, sessions, and commits on one calendar.
- **Shared** shows the cross-agent event log and saved plans.

Use the per-agent browser to read the sessions each agent has recorded for this project.

## Keep the code index current

Atlas separately indexes your codebase so memory retrieval stays grounded in the repository. Its status appears in the [composer](/docs/product/chat), where you can rebuild it. Choose the embedding model in [Settings → Local Models](/docs/product/settings); changing it rebuilds the index after Atlas asks for confirmation.
