Atlas finds the instructions you already gave agents and puts them in one readable list. Use Agent preferences to check what your agents are working from and edit a rule at its source.

## See what Atlas found

Atlas searches existing memory and instruction files for twelve kinds of preference. Each result shows the exact text from the source file, not a summary. Edit it here and Atlas updates that same span in the original file.

<Callout type="info">
  This is a focused view, not a replacement for your files. Rules outside these categories still apply even when they do not appear here.
</Callout>

## Set the strength

Atlas classifies your wording as either:

- **Strong** for a requirement such as “must,” “never,” or “always.”
- **Soft** for guidance an agent should weigh.

Use firmer language in the source when a suggestion should become a rule.

## Browse the categories

| Category | Atlas looks for |
| --- | --- |
| Version control | Commit, push, and staging rules |
| Theme | Light or dark appearance |
| Edit permissions | When agents may change files |
| Testing | Tests and test-driven development |
| Comments & style | Comments and code style |
| Package manager | npm, pnpm, yarn, or bun |
| Commit messages | Message format and style |
| Languages & frameworks | Your preferred stack |
| Architecture | Where logic belongs |
| Communication | Tone and explanation depth |
| Dependencies & files | Rules for adding either |
| Formatting & linting | Formatter and linter expectations |

Each row names its source file and the agent memory it came from. Atlas keeps codebase behaviours separate, and it does not turn a one-off chat message into a standing rule.
