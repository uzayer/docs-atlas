Atlas Agent is the agent built into Atlas. It ships with the app, so there's nothing to install, and it runs through the Atlas gateway on your Atlas account. Usage is billed to your organisation, and no provider key ever sits on your machine.

Like any agent, it reads and edits your code and runs commands. Because it runs inside Atlas, it can also move around the Atlas window for you and, in a Cloud project, read and act in your organisation: find out what a teammate is working on, answer comments on a session, or post a session report to a channel.

## What it needs

Atlas Agent needs three things:

1. **You're signed in** to your Atlas account. See [Your account](/docs/team/accounts).
2. **Your organisation is synced.** A local organisation, including the "Personal" one Atlas creates for you, can't use it. See [Organisations](/docs/team/organisations).
3. **Your organisation has AI access.** An admin grants it and sets the budget. See [AI access & spend](/docs/team/ai-access).

When one is missing, the composer is disabled and a bar above it says why:

| The bar says | What to do |
| --- | --- |
| *Organisation* is local, sync it to use Atlas Agent | Select **Turn on sync**. If you're signed out, Atlas asks you to sign in first. |
| *Organisation* doesn't have AI grants | Ask an admin for AI access. **Request** opens the page where access is granted, and **Refresh** checks again. |

## Start a session

Press <Kbd>⌘T</Kbd> for a new agent chat and pick **Atlas Agent** in the composer. Choose a model from the list, which comes from the gateway and shows the models your organisation can use, and a permission mode.

## Work in your project

Atlas Agent reads, searches and edits files, and runs commands in the project. It also has:

- **[Skills](/docs/context/skills).** Your skills appear as slash commands. Type `/` to see them.
- **[Shared memory](/docs/context/memory).** It reads the project's memory at the start of a session and records decisions, facts and failures as it learns them, so the next agent doesn't start from zero.
- **Built-in commands.** `/compact` summarises the conversation to free up context, `/diff` and `/review` show and review your uncommitted changes, `/goal` sets an objective it keeps in view, `/init` writes or improves `AGENTS.md`, `/status` shows the model and working directory, and `/undo` rewinds the conversation to before your last message.

### Permission modes

Choose a mode in the composer, or press <Kbd>⇧Tab</Kbd> to cycle through them.

| Mode | What it may do |
| --- | --- |
| **Ask** | Asks before edits and commands. The default. |
| **Accept edits** | Edits files in the project without asking. Asks before anything that reaches outside it. |
| **Plan** | Read-only: no edits and no commands that change anything. |
| **Bypass** | Runs everything without asking, with full access to your machine. |

In every mode except Bypass, commands run in an operating-system sandbox. Ask and Accept edits can write only inside the project and have no network access until you approve a command that needs more. Plan can't write at all.

### Questions mid-turn

When a request is ambiguous, Atlas Agent can stop and ask instead of guessing: "Four comments match. Which one?" The question appears as a card above the composer with options to pick from, and the turn waits for your answer. Dismissing the card tells the agent you declined, and it carries on from there.

## Navigate the app

Atlas Agent can act on the Atlas window for you. It can:

- open a file at a line, a diff, or a settings section
- show a panel, or switch to or close a tab
- run any action from the keyboard shortcuts list
- fill in a chat message for you to send
- type a command into a terminal for you to run

It never switches projects, sends a message for you or presses Enter in a terminal, and it won't close a file with unsaved changes. It acts only on the project you're looking at. Each action shows in the chat and in the Logs panel.

Turn this off with **Settings → General → Let Atlas Agent navigate the app**.

## Act in your organisation

In a project whose [capture](/docs/source-control/capture) is **Cloud**, Atlas Agent can read your organisation and act there as you. It works in the organisation that project belongs to, even if the window is showing a different one.

It can read:

- **The roster.** Who's in the organisation, and their roles.
- **Recorded sessions.** Everyone's sessions in this project, or another project in the organisation you name, newest first. It can filter them by person, by date or by keyword, flags the ones still live, and can read any session's prompts, replies and tool calls in full.
- **Comments.** The comment threads on a recorded session.
- **Conversations and your inbox.** Your channels and DMs, and what's waiting in your inbox.

And it can act:

- **Reply to a comment**, and resolve or reopen a comment thread.
- **Send a chat message** to a channel or a person, including a session report: a written summary of a recorded session with a card that opens it on the timeline.
- **Draw in a Space.** Create a page in a conversation's [Space](/docs/team/spaces) and draw a diagram on it.

Admins can also ask for a member's activity: the sessions, checkpoints, lines added and removed, and tokens recorded through Atlas over a period. It counts what Atlas recorded and nothing else, so it's not a measure of anyone's performance.

### Things to ask

- "What is Sam working on right now?"
- "Summarise what the team's agents did on the billing service this week."
- "Find the open comments on my last session and answer them."
- "Write a session report for this session and post it to #backend."
- "Draw the sign-up flow from this session on a new page in the #design Space."

### Anything that reaches someone else asks first

Replying to a comment or sending a message reaches another person in your name, so Atlas Agent asks before it does either. The approval card shows the recipient and the full text before you can allow it. You can allow it once, reject it, or, for a comment reply, allow replies for the rest of the session.

This holds in Bypass mode too: a message the agent tries to send without your approval is refused, and nothing is sent.

Resolving a comment and drawing on a Space page are visible to others and easy to undo, so they don't ask.

### Every call is logged

Each organisation action, including the ones you rejected and the ones that failed, shows in the chat and in the Logs panel. Messages appear under your name, because you approved the exact words.

Turn this off with **Settings → General → Let Atlas Agent act in your organisation**. A running session stops at its next call.

## Limits

- Prompts are text only. Atlas Agent does not accept images yet.
- There is no reasoning-effort control.
- Organisation tools need a Cloud project and act only in the organisation that project belongs to.
- Searches by person or date look at recent sessions, the last 14 days unless you name a period.
- Member activity is for admins only.
