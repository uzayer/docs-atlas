Atlas has one native agent and can run supported coding agents published in the official [Agent Client Protocol registry](/docs/agents/registry). You choose the agent in the composer; Atlas supplies the project and renders the conversation through the same interface.

## Start with Atlas Agent

Atlas Agent is available on every installation and runs in the Atlas process. It uses your Atlas account and the model access attached to your active organisation, so it does not need a provider key from **Settings → API Keys**.

Atlas Agent can read and edit files, search the project, run commands, use [skills](/docs/context/skills), and search [shared memory](/docs/context/memory). Choose its model, mode, and reasoning effort from the controls it exposes in the composer.

## Install an ACP agent

Open **Settings → Agents** to browse the registry. Atlas does not ship a separate built-in copy of Claude Code, Codex, Cursor, OpenCode, Kilo Code, or any other external agent. Installing one from the registry is the source of truth for whether it appears in the agent switcher.

The composer also offers a short list of popular registry agents as one-click installs. These are shortcuts into the same registry, not a different class of integration.

See [ACP registry](/docs/agents/registry) for installation, platform support, updates, and removal.

## Expect capabilities to vary

ACP lets an agent advertise what it supports. Atlas shows only the controls and actions the connected agent provides, including:

- authentication methods
- models, modes, and configuration controls
- commands and permission requests
- session listing, loading, and forking
- images and embedded terminals

An entry shown in Atlas's registry catalogue means Atlas can install and start it. It does not promise that every agent implements every optional ACP capability. Use the repository or website on its registry card for account setup and agent-specific behaviour.

## Keep the record in Atlas

Every agent runs against the open [project](/docs/getting-started/concepts#project). Atlas keeps its chats in session history, and [session capture](/docs/source-control/capture) adds the work to the timeline and links qualifying commits to checkpoints.

Shared memory is capability-based. When memory sharing is on, Atlas offers its memory tools to agents that advertise HTTP MCP support. The agent decides when to call those tools; agents without that capability do not receive memory automatically.
