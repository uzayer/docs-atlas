Atlas doesn't ship one coding agent and ask you to like it. It drives whichever agent you already trust (Claude Code, Codex, Cursor, and the rest) through the [Agent Client Protocol](https://agentclientprotocol.com), and gives all of them the same project, the same [shared memory](/docs/getting-started/concepts#shared-memory), and the same [timeline](/docs/getting-started/concepts#timeline).

The point isn't that you can switch agents. It's that switching doesn't cost you the checkpoints and session history you've already built up.

![The agent picker open in the composer, showing the recommended agents above installed ones](/screenshots/placeholder.svg)

## Every agent works

Anything published to the ACP registry runs in Atlas. Install it from [the registry](/docs/agents/registry) and it joins the agent switcher, works against the same [project](/docs/getting-started/concepts#project), and records [sessions](/docs/getting-started/concepts#session) and [checkpoints](/docs/getting-started/concepts#checkpoint) like everything else. There's no approved list you have to be on.

## What we recommend

Six agents ship with Atlas and sit at the top of the switcher: [Claude Code](/docs/agents/claude-code), [Codex](/docs/agents/codex), [OpenCode](/docs/agents/opencode), [Cursor](/docs/agents/cursor), [Kilo Code](/docs/agents/kilo-code), and [Atlas's own native agent](/docs/agents/atlas). Nothing to install: they're there when you open the app.

These are our recommendations, and the reason is circular in the way recommendations usually are: they're the agents most people reach for, so they're the ones we've done the most work around.

That work is concrete: a brand icon and a fixed position rather than a monogram in an alphabetised list, install and login hints written for that specific agent, and handling for how each one's transcripts load and resume inside Atlas.

Claude Code and Codex have had the most of it.

Everything else runs on the same protocol and gets the same treatment from the parts of Atlas that matter most: memory, timeline, checkpoints, mentions. What it doesn't get is that agent-specific polish, because Atlas doesn't hold per-agent knowledge for the whole catalog.

## What every agent shares

Whichever one you pick:

- It works against the same project (the folder you opened).
- Its sessions land in the same timeline, and Atlas links commits made during them to that session as checkpoints the same way.
- It reads from the same shared memory, so what one agent learned about your codebase isn't lost when you switch to another.

That last one matters more than which agent you picked. An agent you installed five minutes ago starts with the context Atlas has been accumulating all along.

## Authentication and models

Every agent authenticates the way it natively authenticates and offers whatever models it natively offers. Atlas doesn't wrap either, for the recommended six or for anything else.

The difference is only how much Atlas can help you when it goes wrong.

For a recommended agent it can tell you which CLI to install and which login command to run. For the rest, it points you at that agent's own repository and website, both linked on its registry card.
