Choose the coding agent that fits the job. Atlas gives it your project, keeps its work in the same [timeline](/docs/getting-started/concepts#timeline), and carries forward the [shared memory](/docs/getting-started/concepts#shared-memory) your team has built.

Switching agents does not mean starting from zero. Your sessions and [checkpoints](/docs/getting-started/concepts#checkpoint) stay connected to the same project.

## Built-in agents

Atlas includes six agents in the switcher when you open the app:

- [Claude Code](/docs/agents/claude-code)
- [Codex](/docs/agents/codex)
- [OpenCode](/docs/agents/opencode)
- [Cursor](/docs/agents/cursor)
- [Kilo Code](/docs/agents/kilo-code)
- [Atlas Agent](/docs/agents/atlas)

They have dedicated setup guidance and a fixed place at the top of the switcher. Claude Code and Codex have the deepest Atlas integration.

## Add another agent

Atlas also supports agents published to the [Agent Client Protocol](https://agentclientprotocol.com) registry. Install one from [Discover agents](/docs/agents/registry) and it joins the switcher below the built-in agents.

Atlas does not need an approved list for an agent to be useful. If it speaks ACP, it can work with your project.

## What stays the same

Every agent you run in Atlas:

- Works in the project you opened.
- Adds its sessions to the same timeline.
- Links commits it makes back to its session as checkpoints.
- Reads the same shared memory as every other agent.

An agent you installed five minutes ago can use the context Atlas has already gathered about the codebase.

## Authentication and models

Each agent keeps its own authentication and model options. Atlas does not replace them with a generic login or model list.

For the built-in agents, Atlas can offer setup and sign-in help. For registry agents, use the repository and website linked from the agent card for agent-specific instructions.
