title: Introduction
description: What Atlas is, and why it exists.
---

Atlas is source control for coding agents. You open a [project](/docs/getting-started/concepts#project) and run Claude Code, Codex, OpenCode, Cursor, Kilo Code, or any agent from the registry against the same codebase.

Every agent run becomes a [checkpoint](/docs/getting-started/concepts#checkpoint): the commit it produced, linked back to the [session](/docs/getting-started/concepts#session) that made it, with the prompts and reasoning kept together instead of lost the moment the terminal scrolls. Your [timeline](/docs/getting-started/concepts#timeline) is the record of every session and checkpoint in a project.

## One layer over every agent

Every agent Atlas drives reads from and writes to the same on-device [memory](/docs/getting-started/concepts#shared-memory). Switching from Claude Code to Codex mid-task doesn't mean starting over: the new agent inherits the context the last one built up, and the checkpoint trail doesn't reset either.

Atlas doesn't compete with Claude Code or Codex. It's the place you run them, side by side, with a shared record of what each one did.

## The work around the code, not just the code

Alongside the agents, Atlas gives you an editor, terminal, and git diff view for the parts of the loop that are still yours, plus a [knowledge base](/docs/getting-started/concepts#knowledge-base) and research tools for the planning and reading that happens before any code gets written. The goal is a single surface for the whole session, not a chat panel bolted onto an editor.

## Where this is headed

Today, Timeline and [organisations](/docs/getting-started/concepts#organisation) are both single-player-shaped: your own session history, and an account model that can already hold more than one person. Those are the two primitives Atlas is building multiplayer AI on top of: teammates and agents working from the same live context, not just the same repo. That part isn't built yet; what's described in the rest of these docs is. The [roadmap](/docs/roadmap) sets out the unbuilt part in full.
