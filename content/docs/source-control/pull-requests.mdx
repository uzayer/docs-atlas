A pull request opens in its own tab in the [surfaces pane](/docs/product/power-user#surfaces), beside the session that made it. From that tab you can read it, review it, and merge it without switching to a browser.

## Before you start

Atlas talks to GitHub through the GitHub CLI and uses the account it's signed in to. Install [`gh`](https://cli.github.com) and run `gh auth login` once. Atlas never asks for a token of its own.

If `gh` is missing, signed out, rate limited, or GitHub can't be reached, the tab says which one it is. It offers **Retry** and **Open on GitHub**, and when you hit the rate limit it counts down to the reset.

## Open a pull request

- select the pull request badge on a session in the sidebar, or its hover card
- select a pull request row in the [session context](/docs/product/chat#session-context) card
- select a row in the repository's [pull request list](#the-pull-request-list)
- create one with **Create PR**: its tab opens when GitHub confirms it

Opening a pull request that's already open focuses its tab. A second pull request opens in the same column as the first, so you can read down a list in one place. The tabs are saved with the project's layout and come back when you restart Atlas.

## The pull request list

Every pull request in the repository, in a tab of its own. Open it with any of these:

- press <Kbd>⌘T</Kbd> then <Kbd>P</Kbd>
- run **Show Pull Requests** from the command palette
- choose **View all pull requests** in the [session context](/docs/product/chat#session-context) card
- open the project picker at the top of the sidebar and choose the project's **pull requests** item

Each repository gets one list; opening it again focuses the tab.

The list is split into **Authored** (yours), **Review requested** (waiting on you) and **Others**. Each row shows the state, title, number, author, labels, checks, review state, comment count and when it last changed. Select a row to open the pull request in its own tab.

- **Search** matches the title, the number, the branch and the author.
- **State** shows open, closed, merged or every pull request.
- **Involvement** shows everyone's, the ones you're reviewing, or the ones you wrote.
- **Sort** orders by merge readiness, blocked on you, recently updated, newest, oldest, largest or smallest.
- The filter menu narrows by author, label, draft, review state and checks.

Atlas remembers the filters and the sort. Long lists load more as you scroll. With a review state or checks filter on, Atlas loads three pages on its own and then shows **Load more**, so a filter that matches little doesn't page through the whole repository. If a page fails to load, the end of the list says so and offers **Retry**.

## Link a pull request to a session

A session keeps a list of the pull requests that belong to it. A pull request joins the list when:

- the session opens it with **Create PR**
- Atlas finds one opened from the session's branch in the session's own repository. A pull request from a fork that uses the same branch name isn't linked, and sessions on the repository's default branch (such as `main`) aren't searched
- you link it: choose **Link a pull request…** from the session's **⋯** menu in the sidebar or from the session context card, then paste its URL, type its number, or pick one of the repository's open pull requests
- the agent links it with the `link_pull_request` tool

A URL has to name the session's own repository, on the same host. Atlas takes no URL until it has read which repository the session is in; **Link** stays off with a note until then.

Selecting a linked pull request in the sidebar opens its tab. One from another repository opens on GitHub instead.

Unlink one from the session's **⋯** menu, under **Unlink pull request**. A pull request found on the branch stays unlinked after you remove it.

Linked pull requests are kept current in the background: every minute while Atlas is in front, when you come back to the window, and when a turn ends. Open ones are checked most often, quiet and closed ones less, and merged ones not at all. A linked pull request that no longer exists is checked less and less often. The background checks pause while less than a tenth of your GitHub quota is left, so what you open yourself still loads. When GitHub's rate limit is reached, Atlas waits for the reset.

## The header

The header shows the repository, the number (select it to open the pull request on GitHub), the title, the author, and when it last changed. The branch row shows the base and head branches, the files changed, and the lines added and removed. **gh pr checkout** copies the command that checks the branch out.

- **Edit the title** by selecting it, if you have permission to.
- **Update the branch** when it's behind its base: a warning appears on the base branch, and it offers a merge or a rebase.
- **Merge** from the button at the top right. It changes with where the pull request stands: **Ready for review** on a draft, a **Conflicts** badge when it conflicts with its base, **Auto-merge** while checks are still running, and the merge method (**Merge**, **Squash and merge** or **Rebase and merge**) when everything is green. Once auto-merge is on, the button says so.

The **⋯** menu has the rest: refresh, the [agent actions](#hand-it-to-an-agent), mark as draft or ready, merge now, turn auto-merge on or off, choose the merge method, open on GitHub, copy the link or number, close or reopen, and delete the branch once the pull request is merged or closed. Atlas remembers the last merge method you picked.

Merging, enabling auto-merge, closing and deleting a branch ask for a second click before they happen.

The header folds into one line as you scroll down the tab.

## Summary

**Summary** is the first of the tab's views.

- **Reviewers** shows who's been asked and the verdict each one gave. A verdict given before the newest commit is marked as stale. Add or remove a reviewer from the picker next to the list.
- **Labels** lists the labels. Use the picker to add or remove one.
- **Description** renders the description the way GitHub does, including tables, task lists, images, and links to other issues and commits. Edit it in place, with a preview, if you have permission to. React to the pull request from the heading.
- **Checks** lists every check. The failing ones come first, and each one links to its details. The checks pill at the top of the tab opens the same list.
- **Comments** puts loose comments and review threads in one timeline, newest first or oldest first. Bot comments and resolved threads are hidden until you choose to show them, and Atlas remembers that choice. Long conversations load the newest comments first, with a button to show older ones.

## Guide

**Guide** is a tour of the change written by an agent: numbered stops through the code in reading order, each with a short explanation, the lines that matter, notes on specific lines, the other files that belong to it, and the decisions only a maintainer can make. Use it to understand a large pull request before you review it line by line.

Press **Write guide** to have your default agent write one. The agent works in its own read-only checkout of the pull request's head, so your branches and working tree are left alone. A large change takes a few minutes. You can leave the tab while it runs, and Atlas tells you when the guide is ready. If the agent asks for permission to run something, the request appears in the Guide tab, with the full command or input it wants to run, because the agent's session isn't shown anywhere else.

A pull request from a fork asks before the run starts. The fork's code is its author's, and it can include agent instructions or configuration written to steer the agent. Press **Write guide** to go ahead, and check each permission the agent asks for.

Read the guide in order with <Kbd>J</Kbd> and <Kbd>K</Kbd>, or pick a stop from the list on the left. Select a question under a stop, or **Ask about this stop**, to ask about it in a session.

Atlas keeps each guide with the commit it was written for, so it's still there after a restart. When new commits are pushed, the guide says it was written before the latest push and offers **Rewrite**. **Write guide** and **Rewrite guide** are also in the **⋯** menu.

## Timeline

**Timeline** lists everything that has happened to the pull request in order: when it was opened, commits, comments, reviews and their verdicts, review threads on lines of code, label changes, review requests, force-pushes, moves to draft or ready for review, closes and reopens, the merge, and the deleted branch. Press **Newest first** to switch between newest first and oldest first.

Runs of events of one kind collapse into a single row with a count. That covers consecutive comments, consecutive commits, and one person's consecutive label changes, review requests or force-pushes. Click a comment run or a long run of commits to open it. Each commit shows its short SHA, message, authors and lines changed. A verdict given before the newest commit is shown as stale. Resolved threads and dismissed reviews start collapsed. React to a comment or review from its row, or open it on GitHub.

Atlas reads the whole history, so even a pull request with hundreds of events shows all of them. Comment text loads only when you open a comment.

## Code

**Code** shows the pull request's diff in the same viewer as a session's diff, with the file tree, unified or split layout, word wrap, find (<Kbd>⌘F</Kbd>) and the whitespace toggle.

- **Pick a commit** from the menu at the top left to see one commit's changes, or **All commits** for the whole pull request. The commit links on the **Timeline** open Code on that commit.
- **Mark a file viewed** with the **Viewed** box on its header. The file folds away and the count at the top goes up. Viewed marks are kept on GitHub, so they're the same as on github.com and survive a restart. A file that changed after you marked it reads **Changed**.
- **Expand hidden lines** between changes from the fold markers, as in a session's diff.

Large pull requests load a hundred files at a time. The next batch loads as you scroll toward the end, and the count at the top says how many files have loaded. Binary files and files too large for GitHub to show say so in place of their diff.

### Review threads

Review threads appear on the lines they belong to. Reply, resolve or unresolve a thread, and react to its comments in place. **Fix in session** hands an open thread to an agent, as [Fix](#hand-it-to-an-agent) does from the Summary. A thread GitHub has marked outdated, or one on a file that hasn't loaded yet, is listed above the files. With a single commit picked, every thread is listed there.

### Line comments

With **All commits** picked, hover a line of the diff and press the button that appears in the gutter to comment on it. Then choose:

- **Comment now** to post it straight away.
- **Add to review** to hold it until you submit a review. Held comments show on their lines, and the composer button shows how many are waiting.

If new commits move a held comment's line out of the diff, GitHub would refuse the whole review. Such comments are listed above the files and in the composer, each with **Discard**, and the review can't be submitted until they're gone.

## Comment and review

The round speech-bubble button at the bottom right opens the composer. Choose:

- **Comment** to post a comment. You can also close or reopen the pull request with it.
- **Review** to submit a review that comments, approves, or requests changes. Line comments you added to the review from **Code** go with it.

Press <Kbd>⌘↵</Kbd> to send and <Kbd>Esc</Kbd> to put the composer away.

Unsent work stays with the tab when you switch to another tab and back: the comment, the review summary, an open line comment, and the commit picked in **Code**. Sending clears it, and closing the tab discards it.

If the description changes on GitHub while you're editing it, the editor keeps your text and offers **Reload** or **Keep mine**.

## Hand it to an agent

Each action uses your default agent, and the menu names it. Atlas opens a session and puts the task in its composer with the pull request's details attached. Read the task over, change it if you like, and send it yourself.

- **Explain this PR**, in the **⋯** menu, asks for a walkthrough of what the pull request changes and why. It starts a new session in the project. Choose **Explain in this session** to add the task to the session beside the tab instead. Nothing is checked out: the agent reads the diff with `gh pr diff`.
- **Fix** appears on a failing check, a review thread, and a review comment. **Fix findings**, in the **⋯** menu, takes all of them at once. Fixing needs the pull request's branch, so Atlas starts the session where that branch is already checked out, or in a new worktree of its own. Your current checkout is never switched. A failing check comes with its link and the command to read its log. A review thread comes with its file, line and replies.

When the agent has made the fix, push it from the session yourself. Atlas never pushes for you. Fix is offered only on open pull requests.

Atlas removes a Fix worktree once nothing needs it: it's at least three days old, no unsettled session works in it, it has no uncommitted or untracked changes, and its commits are on a branch. The branch itself is kept. Atlas checks once each time it starts.
