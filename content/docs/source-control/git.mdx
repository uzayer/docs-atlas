Agents create diffs. Use source control to read them, stage the parts you want, and make the commit.

## Open source control

Source control is a tab in the [surfaces pane](/docs/product/power-user#surfaces), beside the session. Open it any of these ways, and use the first two again to close it:

- press <Kbd>⌘⇧B</Kbd>
- choose **Source control** in the sidebar
- press <Kbd>⌘T</Kbd> then <Kbd>G</Kbd>

Its sections are **Changes**, **Commit** (the git graph) and **GitHub**. The [session context](/docs/product/chat#session-context) overlay also offers the branch, the next git action and **Open Source Control** without leaving the session.

## Work in Changes

Fetch, pull, push, or publish a new branch from the toolbar. The Pull and Push buttons show how many commits you're behind and ahead. Use the branch switcher to find, create, delete, check out, or merge a branch.

In **Changes**, review each modified file, stage or discard files and hunks, then write the commit summary, description, and optional co-authors. **Revert all** discards every unstaged change, after you confirm.

To change the previous commit instead of making a new one, tick **Amend last commit**. Leave the summary empty to keep the original message.

Resolve conflicts from the same view by taking ours or theirs, opening the file, or marking a completed resolution.

## Fetch in the background

With **Settings → Source Control → Auto-fetch from remote** on, Atlas runs `git fetch` for the open project when it opens, when Atlas regains focus, and every few minutes. The Pull badge then shows what the remote has.

Auto-fetch only updates remote-tracking branches. It never pulls, merges, or touches your files. It's on by default.

## Read history and stashes

<Video youtube="2ebqYJYHuV0" title="Tracing a commit back to the agent that wrote it" />

In **Changes**, switch to **History**. Select a commit to copy its SHA, revert it, cherry-pick it, tag it, undo it into staging, or reset to it.

When session capture is on, a commit an agent worked on shows **Produced by N sessions**, listing each session by title. Select one to open it in the [timeline](/docs/team/timeline) and read the prompts, reasoning and tool calls behind the commit. See [Session capture](/docs/source-control/capture#how-commits-become-checkpoints) for how Atlas makes that link.

Use **Stashes** to save the working tree and restore it later.

## See the git graph

The **Commit** section draws the repository's history across every branch as a graph. It refreshes when commits, checkouts and fetches happen, including ones made in a terminal. Expand it to the full window for a long history.

You can also open it from the command palette (<Kbd>⌘K</Kbd>) with **Show Git Graph**.

## Clone reference repositories

The **GitHub** section lets you search public GitHub repositories and clone them into the project's `.atlas/repos/` directory as reference material for you and your agents. Because they live under `.atlas/`, they stay out of your own repository.

Clones are shallow and track one branch. Switch a clone to another remote branch, fetch its latest commit, open it on GitHub, or delete it from the same list.

## Read a diff

Review diffs inline as a searchable unified view, or open a substantial change full-window for a side-by-side comparison, file list, and minimap.

## Handle failures

Atlas identifies common git failures, including authentication, protected branches, rejected pushes, conflicts, hooks, and signing. It tells you what failed and keeps git's own output available.
