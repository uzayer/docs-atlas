Use the timeline to answer a simple question: which agent session produced this commit? Atlas keeps sessions and [checkpoints](/docs/getting-started/concepts#checkpoint) together for each project.

The timeline shows projects with [session capture](/docs/source-control/capture) turned on. Open it from **Timeline** in the sidebar. It spans every project in the active [organisation](/docs/organisation/organisations).

## Follow a commit back to its work

Open a commit from [Source Control](/docs/source-control/git) to see the sessions that contributed to it. Open a session in the timeline to see the commits it produced.

Atlas stores this record locally in the project's Atlas directory. It works offline and never requires a network connection.

## Let Atlas link the work

Atlas watches repository history without installing git hooks, changing git configuration, or writing refs. It can therefore connect work committed from Atlas, another editor, or a terminal.

For existing files, Atlas links a session when the commit includes a path the agent touched. For new files, the committed content must match the agent's output. This keeps normal follow-up edits linked while avoiding credit for files you replaced yourself.

Once Atlas settles a touched path, it stops using that touch to nominate future commits. Merge commits do not create checkpoints, and a purely human commit stays unlinked.

## Keep sessions without commits

Atlas records a session even when it never produces a commit. Git is optional: non-repository folders still keep sessions, but cannot produce checkpoints.
